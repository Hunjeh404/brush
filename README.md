# 올림포스 양치 모험

아이패드 **세로** 화면 우선, 휴대폰 세로 대응. 치실 → 칫솔질 → 보상 → 공간 수집·꾸미기로 이어지는 오프라인 우선 웹 앱(PWA)입니다.

## 빠른 실행: GitHub Pages

1. 새 GitHub 저장소(예: `olympus-brush`)를 만듭니다.
2. 이 폴더의 파일을 저장소 루트에 올립니다. `node_modules`와 `dist`는 올리지 않습니다.
3. 저장소 **Settings → Pages → Source → GitHub Actions**를 선택합니다.
4. `main`에 푸시하면 포함된 `.github/workflows/pages.yml`이 검사·테스트·빌드·배포합니다. 필요하면 Actions에서 수동 실행합니다.
5. 생성된 HTTPS 주소를 아이패드 Safari에서 열고 **공유 → 홈 화면에 추가**합니다.
6. 하단에 **오프라인 준비 완료**가 표시될 때까지 인터넷 연결을 유지합니다. 전체 앱·이미지·얼굴 모델·WASM을 한 번 내려받습니다(약 31.8 MiB).
7. 홈 화면 앱을 실행해 부모 비밀번호와 복구 코드를 설정합니다. 이후 인터넷 없이 이용할 수 있습니다.

GitHub Pages에서 앱 파일을 전달합니다. 선택적으로 스도쿠와 같은 Supabase 프로젝트의 Google 로그인과 가족 프로필을 사용하며, 양치 기록은 별도 테이블에 저장합니다. 외부 AI API, 분석·광고 추적은 사용하지 않습니다. 최초 설치·업데이트·로그인·동기화에는 인터넷이 필요합니다.

### 빌드 없이 배포

동봉된 `dist/` 내용 전체를 정적 HTTPS 호스팅에 올릴 수도 있습니다. `dist`의 내용 자체가 배포 루트가 되게 하세요. GitHub Pages에서 브랜치 배포를 사용할 경우 `dist` 내용만 별도 배포 브랜치 루트에 두면 됩니다.

파일 앱에서 `index.html`을 직접 여는 `file://` 실행은 지원하지 않습니다. 카메라와 PWA 설치는 HTTPS(개발 시 localhost)가 필요합니다.

## 기능과 기본값

- 치실 하루 2회(아침·저녁), 횟수 0~3회 설정. 치실은 시간제한 없이 여섯 구역을 직접 완료 확인합니다.
- 칫솔질 하루 2회, 횟수 1~3회 설정. 기본 전동칫솔, 일반칫솔 선택 가능.
- 기본 5분, 2~10분 범위에서 30초 단위 선택. 네 구역의 바깥·안쪽·씹는 면 안내.
- 완료한 루틴의 치실 +10, 칫솔질 +10. 같은 날짜·회차·단계는 보상을 중복 지급하지 않습니다.
- 양치를 **시작한 뒤 조기 종료를 확인한 경우에만** 티탄 공격 1회. 앱 미사용, 치실 단계 종료, 준비 단계, 화면 전환·전화·앱 종료에는 공격하지 않습니다.
- 화면이 숨겨지면 자동 일시정지합니다. 다시 열고 `이어서 하기`를 선택합니다. 실행 중 진행은 약 1초마다 단말에 저장되며 갑작스러운 OS 종료 시 직전 저장 이후의 짧은 진행은 유실될 수 있습니다.
- 손상은 현재 공간의 여섯 자리 각각 최대 3단계. 수리 한 단계에 빛 4개. 한도에서도 공격은 기록되며 수집품은 삭제되지 않습니다.
- 꾸미기는 기본 회차당 3분(0 / 30초 / 1 / 2 / 3 / 4 / 5 / 10분 선택). 수리·배치 중에만 차감. 나갔다 돌아와도 남은 시간이 유지됩니다. 새 보상 회차 완료 시 기본 시간으로 다시 열리며 남은 시간을 더하지 않습니다.
- 정원·바다 궁전·달빛 숲·태양 신전·지혜 도서관·꽃 들판·보석 공방·구름 항구·천상 궁전, 총 9개 완성 일러스트 공간. 공간마다 벽화 1개와 보물 5개를 놓는 고정 슬롯. 오브젝트 크기·회전·원근을 사용자가 변경하지 않습니다.
- 부모 비밀번호 보호, 5회 오류 시 30초 대기, 화면 전환 시 설정 잠금, 복구 코드, JSON 백업·복원.

## 로컬 처리와 저장

- 얼굴 추적: MediaPipe Face Landmarker 0.10.32. 모델과 WASM은 빌드 단계에서 준비하고 SHA-256을 검증해 배포 파일에 포함합니다. CPU에서 낮은 빈도로 실행하여 태블릿 부하를 줄였습니다.
- 전면카메라 영상은 단말 메모리에서 얼굴 위치 안내와 양치 타이머 제어에 사용하며 녹화·저장·전송하지 않습니다. 마이크 권한을 요청하지 않습니다.
- 얼굴 위치·거리 보조 기능입니다. 치아의 청결도, 칫솔 압력, 치실 접촉, 실제 닦은 치아를 판정하지 않습니다. 카메라를 켠 모드에서는 얼굴이 감지된 동안만 양치 시간이 진행됩니다. 얼굴이 사라지거나 인식 오류·카메라 연결 끊김·영상 멈춤이 발생하면 시간이 멈추고, 얼굴이 다시 감지되면 자동으로 이어집니다. 수동 일시정지는 자동 해제하지 않으며, 멈춘 시간은 나중에 더하지 않습니다. 카메라 권한을 허용하지 않았거나 모델 준비에 실패한 경우에도 시간을 진행하지 않습니다. 부모 설정에서 카메라를 끈 경우에만 카메라 없이 타이머를 사용할 수 있습니다.
- 음성은 OS에 설치된 한국어 음성 중 `localService` 음성만 사용합니다. 오프라인 음성이 없거나 OS에서 재생을 허용하지 않으면 화면 안내를 사용합니다. 필요하면 기기의 한국어 음성을 먼저 다운로드합니다.
- 기록·설정·보상·손상은 IndexedDB, 앱 파일은 Service Worker Cache Storage에 저장합니다.
- 부모 비밀번호/복구 코드는 랜덤 솔트와 PBKDF2-SHA256(150,000회) 해시만 저장합니다. 로컬 부모 잠금은 개발자 도구나 단말 데이터 초기화를 막는 OS 수준의 보안 기능은 아닙니다.
- 백업에는 비밀번호 해시와 진행 중 모험이 포함되지 않습니다. 복원은 모든 공간·배치·기록을 교체하고 현재 비밀번호를 유지합니다.
- 로그인 없이 사용한 기록은 단말별로 보관합니다. 로그인 후 같은 가족 프로필을 선택하면 양치 기록·보상·공간·설정·진행 중 모험을 동기화합니다. 부모 비밀번호 해시는 서버로 보내지 않습니다. 첫 로그인에는 인터넷이 필요하며, 이미 선택한 프로필은 오프라인에서도 사용할 수 있습니다.
- 기록은 먼저 IndexedDB에 저장하고, 양치 중에도 약 1초 단위 저장 후 계정과 자동 동기화합니다. 변경이 없을 때는 5초마다 확인하고 앱 복귀·온라인 복구 때에도 확인합니다. 양쪽 기기가 다르면 서버 잠금 안에서 누적 양치 시간(완료·조기종료·진행 중 시간 합계)이 긴 전체 기록을 채택합니다. 시간이 같으면 최근 변경을 채택하며 완전히 같은 기록은 재저장하지 않습니다. 코인·구매 목록은 합산하지 않습니다. 변경 시각은 기기 시계에 의존합니다. 다른 기기 기록을 적용할 때 현재 양치는 일시정지되고 홈에서 이어서 할 수 있습니다. 서버에는 직전 10개 버전을 보관합니다.
- 첫 계정 연결 시 로그인 전 기록도 같은 기준으로 자동 비교합니다. 서버 확인이 끝난 뒤 정확히 해당 guest revision만 정리하며, 실패하거나 다른 탭이 수정했으면 지우지 않습니다. 부모 PIN은 기기에 유지하고, 계정별 오프라인 사본도 유지합니다. 로그아웃하면 빈 기기 기록으로 돌아가며 계정 기록은 남습니다. 게스트 기록이 없어도 자동 동기화합니다.
- 같은 단말에서 여러 탭으로 열면 변경 충돌을 감지해 덮어쓰기를 중단합니다.

## 개발

Node.js 22 이상:

```sh
npm ci --ignore-scripts
npm run prepare:offline
npm run check
npm test
npm run build
```

`dist/`가 배포 가능한 정적 결과물입니다. `prepare:offline`은 고정된 npm 패키지에서 WASM을 복사하고 Google 공식 주소에서 버전 1 얼굴 모델을 내려받습니다. 세 파일 모두 `ASSET-CHECKSUMS.json`의 SHA-256과 일치해야 빌드를 진행할 수 있습니다. 이미 준비된 파일이 일치하면 다시 내려받지 않습니다. 최초 개발 준비와 GitHub 빌드는 인터넷 연결이 필요합니다.

배포 결과물에는 `vendor/`와 `models/`가 모두 포함되어 런타임에 npm/CDN 다운로드가 없습니다. 빌드는 같은 파일을 원본과 `dist`에 완전한 캐시 목록으로 기록합니다.

로컬 수동 시험은 `npm run build` 후 `python3 -m http.server 4173 --directory dist`로 localhost에서 열 수 있습니다. 다른 기기에서 개발 서버의 일반 HTTP IP 주소를 열면 카메라가 막힐 수 있으므로 iPad 시험은 GitHub Pages HTTPS 주소를 사용하세요.

## 검증 범위

- 자동 검증: 설정 범위, 보상 중복 방지, 공격 조건·한도, 수리 비용, 고정 슬롯, 꾸미기 만료, 타이머 일시정지, 얼굴 부재·복귀·영상 멈춤·인식 오류·권한 거부 시 타이머 제어, PIN 잠금, 백업 검증, 저장 충돌, 앱 DOM 전체 흐름, 파일 기반 Service Worker 오프라인 응답.
- 실제 Safari/iPad 화면 렌더링과 카메라 추적 정확도·성능은 이 빌드 환경에서 시험하지 못했습니다. 자동 DOM 검증은 실제 브라우저 시험을 대신하지 않습니다.
- 실기기 점검: 설치 → 비밀번호 설정 → 카메라 권한 → 치실 6구역 → 양치 → 홈 화면/전화 후 재개 → 완료 보상 → 3분 꾸미기 → 비행기 모드로 앱 재실행 → 백업·복원.
- 양치 기본값 5분과 치실 2회는 요청에 따른 사용자 설정이며 보편적 의료 권고가 아닙니다. 일반적인 권고는 하루 2회 약 2분 칫솔질과 하루 1회 치간 청소입니다. 아이의 연령·칫솔 제품·치과 지침에 맞춰 조정합니다.

참고: https://www.nhs.uk/live-well/healthy-teeth-and-gums/how-to-keep-your-teeth-clean/ · https://www.mouthhealthy.org/all-topics-a-z/flossing · https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/web_js · https://webkit.org/blog/14403/updates-to-storage-policy/

이미지 출처와 라이선스 정보는 `ASSET-SOURCES.md` 및 `THIRD-PARTY-NOTICES.md`를 확인하세요.

## 공간 수집 확장 (v1.1)

- 기존 보물 9종에 8개 테마 × 6종을 더해 총 57종. v1.3부터 새 보물은 20 / 35 / 50 / 70 / 90 / 110빛이며 기존 가격은 유지합니다.
- 새 공간은 120~400빛. 수집함의 공간 탭에서 미리 보고 남은 꾸미기 시간이 있을 때 구매합니다. 구매한 공간 방문은 시간·비용 제한이 없습니다.
- 모든 보물은 모든 공간에서 사용할 수 있습니다. 같은 보물을 여러 공간에 전시해도 다시 구매하지 않습니다.
- 공간별 배치·손상은 독립적으로 저장합니다. 보관하기는 소유권을 유지하며 해당 자리만 비웁니다.
- 기존 schema 1 기록과 백업은 schema 2로 이관합니다. 보유 빛·아이템·배치·손상·설정·인증 정보·진행 중 양치는 유지됩니다. 백업 복원 시 인증 정보는 현재 기기 값을 유지하고 진행 중 양치는 복원하지 않는 기존 정책을 따릅니다.
- 검증: 기존 양치 흐름, 구버전 저장 이관, 공간 구매/재방문/개별 배치, 전체 공간 백업 복원, 중복 결제 방지, 공간별 손상 및 오프라인 캐시를 포함한 25개 테스트. 로컬 브라우저에서도 구름 항구 구매 → 6종 배치 → 원래 정원 왕복 → 새로고침 보존 확인.
- 원화는 내장 이미지 생성 도구로 제작했습니다. 프롬프트는 art/expansion-prompts.json, 테마 명세는 art/expansion-themes.json, 시트에서 분리한 범위는 art/sprite-bounds.json에 있습니다.

## 계정 저장 구성

`cloud-config.js`는 공개 Supabase URL과 publishable key만 포함합니다. service-role 키는 사용하지 않습니다. SDK는 고정 버전으로 빌드해 오프라인 캐시에 포함합니다.

- 기존 `profiles`, `profile_access`, `private.can_act` 및 가족 프로필 생성 RPC를 재사용합니다. 양치 전용 `brush_profiles`는 양치 앱에서만 공유한 프로필도 함께 반환합니다. 스도쿠 점수·코인·게임 기록은 변경하지 않습니다.
- `supabase/migrations/0001_brush_cloud.sql`: 양치 전용 저장 테이블, 사용자별 읽기 정책, 권한 검사와 버전 충돌 검사가 있는 저장 RPC. 클라이언트의 테이블 직접 쓰기는 차단합니다.
- Supabase Authentication → URL Configuration → Redirect URLs에 배포 주소 `https://hunjeh404.github.io/brush/`를 추가해야 합니다. 기존 Sudoku Site URL과 허용 주소는 유지합니다. Google 제공자는 기존 설정을 공유합니다.
- 인증 저장 키는 `olympus-brush-auth-v1`이며 스도쿠 로그인 세션과 독립적입니다. 최초에는 양치 앱에서도 Google 로그인을 선택해야 합니다.
- 자동 검증은 오프라인 재시도, 동시 수정, 계정 전환 중 응답, 비밀번호 해시 제외, 자동 충돌 해결 및 프로필 분리를 포함합니다. Google 계정 선택부터 복귀까지는 실제 계정으로 별도 확인이 필요합니다.

- `0002_brush_shared_profiles.sql`은 양치 앱에 한정된 공동 접근 권한을 추가합니다. 기존 스도쿠 공유 권한은 넓히지 않습니다. 지정된 공동 프로필은 첫 로그인 때 기본 선택됩니다. 계정 이메일과 실제 복구 지급 내역은 소스 코드에 넣지 않습니다.
- 앱 업데이트는 `updateViaCache: none`으로 확인합니다. 새 파일 전체를 캐시에 저장한 후 서비스 워커가 활성화되며, 현재 화면은 양치·꾸미기·입력·저장이 끝난 시점에 새로 열립니다. 하단에서 버전과 업데이트 상태를 확인할 수 있습니다. 기존 버전에서 처음 넘어오는 경우 인터넷 연결 후 앱을 완전히 닫았다 다시 열어주세요. 기기 기록을 삭제할 필요는 없습니다.

보안 검증: 로그인 사용자가 호출하도록 설계한 세 RPC의 SECURITY DEFINER 경고는 의도된 권한 경계입니다. 빈 search_path, 명시적 사용자/프로필 검사, 익명 실행 차단, 테이블 직접 쓰기 차단, 소유자·공동 사용자·무관한 사용자·익명 테스트를 확인했습니다. `supabase/verify-brush.sql`은 모든 테스트 데이터를 롤백합니다.
